## Platform

## Users

- **Оператор (роль User)** — сотрудник футбольной площадки. Принимает звонки от игроков и заводит брони за них: имя и телефон клиента, дата, час, заметка. Работает в основном с телефона, у поля или в дороге, часто на улице.
- **Администратор (роль Admin)** — владелец или управляющий. Смотрит аналитику (выручка, остаток к оплате, загрузка площадок, часы пик), ведёт площадки, пользователей, все брони и расписание. Тоже в основном с телефона.
- **Гость** — игрок без логина. Смотрит список площадок и занятость на сегодня, бронирует звонком по номеру площадки.

## Product Purpose

Futsal — бронирование часовых слотов на футбольных площадках в Алмалыке (Узбекистан). Оператор быстро видит свободные часы и фиксирует бронь по звонку; админ видит, сколько денег получено и сколько ещё должны; гость сам проверяет, свободно ли поле, прежде чем звонить. Успех: бронь заводится за секунды с телефона, двойных броней нет, оплата каждого слота понятна с одного взгляда.

## Operating Context

- Единица бронирования — один час, от времени открытия до закрытия площадки.
- Статусы оплаты: не оплачено, предоплата (с суммой), оплачено. Статусы брони: активна, отменена.
- Цены в тысячах сумов за час.
- Прошедшие часы забронировать нельзя; прошедшие брони остаются доступными для обновления оплаты.
- Гости видят только «занято/свободно», без данных клиентов.

## Capabilities and Constraints

- Языки интерфейса: русский и узбекский (переключатель ru/uz), все строки через i18n.
- Стек: React 19, Vite, Tailwind CSS v4, TanStack Query, react-router, lucide-react, react-hot-toast.
- Деплой: play.hypex.site; CSP разрешает шрифты только с self и fonts.googleapis.com / fonts.gstatic.com, картинки — self, data: и https:.
- Фото площадок — внешние https-ссылки, которые вводит админ; есть заглушка `/venue-placeholder.svg`.

## Brand Commitments

- Футбольная тематика должна читаться.
- Название продукта — Futsal. Текущий визуал не обязателен к сохранению.
- Пользователь сознательно выбрал стандарт категории (обычное приложение бронирования, исполненное безупречно), а не экспериментальный визуальный мир.
- Планка качества: Playtomic (бронирование слотов), Fresha / Booksy (рабочий календарь и статусы оплаты), Linear / Stripe Dashboard (аккуратность админки и аналитики). Ориентир по уровню исполнения, не по внешнему виду.

## Evidence on Hand

Реальные данные — площадки, брони и статистика из API. Отзывов, клиентов, цифр для маркетинга нет; не выдумывать.

## Product Principles

1. Скорость оператора важнее украшений: свободный час и кнопка брони видны сразу.
2. Деньги прозрачны: статус оплаты каждого слота читается без раскрытия деталей.
3. Телефон — основной экран; на улице при ярком свете всё должно оставаться читаемым.
4. Гостю — минимум: свободно ли поле и куда звонить.
